# X保存 v1.02

Xの動画と、録音が公開されているスペースの音声をスマホに保存するアプリです。

**[アプリをダウンロードする](https://github.com/muya-nakama/X-tool/releases/download/v1.02/X-tool-v1.02.apk)**

Android 10以降の対応端末用です。Galaxy S24 Ultraでの利用を想定しています。作者：仲間六夜 feat. ChatGPT。

## 入れ方

1. 上の「アプリをダウンロードする」を押します。
2. ダウンロードした **X-tool-v1.02.apk** を開きます。これがアプリのインストール用ファイルです。
3. 端末の案内に従ってインストールします。「不明なアプリのインストール」の許可を求められたら、使っているブラウザや「マイファイル」の設定を確認してください。

GitHubのコードやZIPをダウンロードする必要はありません。Termuxも不要です。

## 動画・スペースを保存する

1. Xで投稿やスペースのリンクをコピーします。
2. 「X保存」を開き、「リンクを貼り付け」を押します。
3. 「保存する」→「はい」を押します。
4. 保存が終わったら「保存したファイルを開く」で再生できます。

Xの共有ボタンから「X保存」を選ぶこともできます。保存する内容は自動で判別します。スペースは映像ではなく音声で保存します。

## 保存したファイルはどこ？

スマホの「マイファイル」などで、次のフォルダを開いてください。

- 動画：**Download → X保存 → 動画**
- スペースの音声：**Download → X保存 → スペース**

動画はMP4、音声はM4Aという形式です。

## ログインが必要と表示されたら

最新版 v1.02では、ファイルを用意せずにログインできます。

1. 「アカウント」→「＋ 新しいアカウントでログイン」を選びます。
2. 表示されたXの画面で、ユーザー名とパスワードを入力してログインします。
3. 「このアカウントを保存」を押して、見分けやすい名前を付けます。
4. 保存に使うアカウントを選び、動画の保存をもう一度試します。

複数のアカウントを保存して選べます。「保存したアカウントを管理」から、名前の変更・ログインし直し・端末からの削除もできます。

Google・Appleのボタンからのログインには対応していません。Xのユーザー名とパスワードを使ってください。X側がアプリ内のログインを受け付けない場合は利用できません。X公式アプリのログイン状態を自動で引き継ぐ機能はありません。

## 更新する・前の版に戻す

- **「アプリの更新を確認」**：新しいアプリがあるか調べます。見つかったらダウンロードページを開けます。更新のインストールは自分で行います。
- **「取得エンジンを更新」**：動画を取り出す機能を更新します。急に保存できなくなったときに試してください。
- **画面上部の版の切り替え**：アプリを消さずに、最新版 v1.02と旧版 v1.00を切り替えられます。保存中は切り替えできません。

旧版 v1.00には以前のファイル式ログインが残っています。画面で入力してログインする場合は、最新版 v1.02を選んでください。版を切り替えても、最新版で保存したアカウントとダウンロード済みの動画は残ります。

この切り替えで戻るのは画面と保存の処理です。アプリのインストールに関する不具合や、共通の動画取得機能までは元に戻りません。

## 履歴・ログイン情報について

ダウンロード履歴は残しません。作業中の一時ファイルは処理が終わると削除します。強制終了した場合は、次に保存や取得機能の更新を行うときに片付けます。

保存したログイン状態は、他のアプリから読めない場所に暗号化して保存します。`.ログイン情報.txt` はアプリが自動で作るので、手で作ったり選んだりする必要はありません。パスワードをアプリが読み取って保存することはありません。

アプリをアンインストールすると、保存したログイン状態は消えます。入れ直した後は再ログインが必要です。Downloadフォルダに保存済みの動画・音声は残ります。

GitHubはアプリの配布と更新確認に使います。アプリで入力した動画のリンクや、保存した動画・音声をGitHubへ送りません。

## 保存できないとき

「取得エンジンを更新」を試してから、投稿やスペースのリンクを貼り直してください。短い `t.co` のリンクではなく、`x.com` または `twitter.com` の投稿・スペースのリンクを使ってください。

削除された動画や、録音が公開されていないスペースは保存できません。配信中・開始前・終了直後で録音の準備中のスペースも対象外です。X側の制限によって保存できない場合もあります。

## 確認できていること

- 自動テスト10件と、アプリのインストール用ファイルの作成は成功しています。
- 指定された公開動画1件は、アプリと同じ取得エンジン・設定でダウンロードし、映像と音声を最後まで読み込めることを確認しました。
- Android実機でのインストール・ログイン・版の切り替え・スペースの保存は未確認です。以前のインストール不具合が直ったと確認できた版ではありません。

インストールできないときは、端末に表示されたメッセージを確認してください。前のアプリと新しいファイルの組み合わせによって、上書きできない場合があります。

### 自分でAPKを作る

GitHubのActions → Build APK → Run workflowで実行します。成功した実行のArtifacts → `X-tool-APK` をダウンロードし、ZIP内の `app-debug.apk` を使います。main/masterへの通常のpushでも実行します。手動実行時に配布の項目を選ぶと、テスト成功後にReleaseを作成します。

Android 10以降・arm64向け。動画の保存にはMediaStoreを使用します。保存中はフォアグラウンドサービスと通知を使います。ログイン情報はAndroid Keystoreの鍵でAES-GCM暗号化し、最大20アカウントを保存します。Androidの自動バックアップは無効です。

## 開発・署名

JDK 17、Gradle 8.11.1、Android SDK 35を使用する。`gradle :app:testDebugUnitTest :app:assembleDebug`でテストとAPK生成。Gradle Wrapperは同梱せず、Actionsで指定版Gradleを導入する。

初版はdebug APK。GitHubの実行環境ではdebug署名鍵が再生成される場合があり、別ビルドへの上書きインストールに失敗することがある。その場合は旧アプリをアンインストールして入れ直す（保存済みのDownload内ファイルは保持される）。継続利用時は固定署名鍵へ移行する。

## 使用ライブラリ

## new / old の更新ルール

- `new/`：最新版の画面・取得処理と `version.json`。
- `old/`：直前に配布済みの版の同じソース。二世代より前は同梱しません。
- `shell/`：共通の起動・版の切り替え。
- `app/`：Android設定、生成ルール。
- `scripts/prepare_versions.py`：最新配布タグの `new/` を、次回ビルドの `old/` へコピーします。

次の版を作るときは `new/` を改修し、`new/version.json` のversionとversionCodeを増やします。ビルド時に直前の配布タグからoldを準備し、テスト成功後の公開処理でoldもリポジトリへ反映します。例えばv1.03ならnew=v1.03、old=v1.02です。途中のビルド失敗や未公開の改修はoldに昇格させません。同じ版を再ビルドした場合はoldを維持します。取得エンジンとAndroid設定は共通のため、二枠でAPK全体が完全に独立するわけではありません。
