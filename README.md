# MOVIE&AUDIO-TOOL v1.11

リンクを貼って、動画や音声をスマホに保存するAndroidアプリです。旧名はX-toolです。

**[アプリの配布ページ](https://github.com/muya-nakama/X-tool/releases/tag/v1.11)**

Android 10以降・arm64の端末用です。配布ページのAPKを開いてインストールしてください。コードやZIP、Termuxは不要です。

## 保存する

1. 動画や音声のリンクをコピーして、アプリの「リンクを貼り付け」を押します。
2. 「動画・音声を読み込む」を押します。
3. タイトル・サムネイル・長さを確認します。
4. 「動画」か「音声のみ」を選び、画質・形式・推定容量を選びます。
5. 「ダウンロード」→「はい」で保存します。終わったら「保存したファイルを開く」で再生できます。

SNSの「共有」からアプリを選ぶこともできます。

Xの動画・録音済みSpace、YouTube・Shorts、Instagram、TikTok、Facebook、ニコニコ、Twitch、Pornhubなどを共通の取得エンジンで扱います。他サイトのURLもエンジンが対応していれば取得できます。サービス側の変更・ログイン・地域制限などで保存できない場合があります。複数動画の投稿は各動画のURLを指定してください。ライブ配信やDRM付きの動画は対象外です。

## 取得に失敗する場合

通信の応答を60秒まで待ち、一時的な通信エラーは間隔を空けて再試行します。動画全体を60秒で止める設定ではありません。失敗時は画面の案内に従って通信状態やログインを確認してください。サイト側の制限や仕様変更は、待ち時間を延ばしても解消しない場合があります。

## GoFile Centerの保存

GoFile Center（gofile.center・gofile.diy）の個別動画ページのリンクを、そのまま貼り付けて読み込めます。動画・音声を選ぶ手順は他サイトと同じです。パスワード付きリンク、期限切れ・非公開のリンク、フォルダーの一括保存には対応していません。動画情報・配信形式の取得まで確認しており、Android実機での保存完了は未確認です。

## 保存場所

**Download → MOVIE&AUDIO-TOOL → サービス名 → 動画 または 音声 → 投稿者**

映像と音声が別々の場合は、画質を保ってMKVにまとめます。音声は元の形式を保って保存します。再生できない形式は、対応するプレーヤーで開いてください。推定容量は実際の通信量や完成ファイルと違う場合があります。音声を動画から取り出す場合は動画分の通信量も表示します。

ハイレゾの条件を確認できた音声には「ハイレゾ」、配信元に立体音響の表記があるものにはその表記を出します。多チャンネルと立体音響は別々に表示します。元にない音質を追加する機能ではありません。配信元が形式情報を出していない場合、判定できません。

## 同じファイルの再ダウンロード

同じ動画・音声・形式を選んだ場合は、以前の記録と元の保存先を確認します。ファイルがあれば「既にこのファイルは存在します」と表示し、保存済みファイルを開けます。元の場所になければ「ファイルは削除または移動されています」と表示し、確認後に再ダウンロードします。移動先の探索はしません。

記録はv1.06で保存が成功したファイルから対象です。更新前の版には記録がないため、既存ファイルを自動では照合できません。動画と音声、異なる画質・形式は別々に扱います。

## ログイン・アカウント切替

「設定」でサービスを選び、「＋ ログイン」を押します。公式ログイン画面で入力した後、「このアカウントを保存」で表示名を付けます。同じ設定から使用するアカウントの切替、名前変更、ログインし直し、端末からの削除ができます。X、YouTube、Instagram、TikTok、Facebook、Twitch、ニコニコの設定を用意しています。

サービス側がアプリ内のログインを受け付けない場合、そのログイン方法は使えません。Google等のアプリ内ログインは拒否される場合があります。サービスを設定に表示していることは、全ての端末でログインできる保証ではありません。

ログイン状態はAndroidの安全な鍵で暗号化して、アプリ専用の場所に保存します。パスワード自体はアプリで保存しません。他サービスにログイン情報を渡しません。重複確認のため、保存成功時に識別子と保存先を端末内へ記録します。URLやログイン状態はこの記録に含めません。

## 詳細設定

「設定」→「詳細設定」で、初回は4文字以上のパスワードを確認入力して登録します。次回からはパスワードを入力して開きます。一部サービスのログイン・アカウント管理はこの中にまとめています。保存したアカウントはページを隠していてもダウンロードに使えます。

詳細設定を閉じる、別画面・別アプリへ移る、画面を消すとロックし直します。タスク終了や再起動でも解除状態は残りません。パスワードとログイン情報はアプリの更新後も保持します。

## 更新と前の版への切替

起動時に更新の有無を確認します。「設定」→「アプリを更新」→「更新する」で更新用ファイルを取得し、Androidの確認画面で上書き更新します。初回は、このアプリからのインストール許可が必要です。同じ署名の更新ではログイン情報と設定を残します。取得エンジンはアプリを入れ直さず更新できます。

**v1.04以前からの移行は別です。以前の署名鍵が保存されていないため、そのまま上書きできる保証はありません。今のアプリを削除しないでください。** 署名が違う更新ファイルはアプリが止めます。固定署名による更新は、固定署名の版を導入した後の更新が対象です。

「設定」→「使用する版」で、最新版v1.11と前の配布版v1.10を切り替えられます。取得エンジンやAndroid設定は共通です。保存中・更新中は切替できません。

Wi-Fi・有線以外で100MB以上の保存をする場合は、毎回確認を表示します。警告する容量は設定で変更できます。容量不明の場合も確認します。大容量保存中にWi-Fiが切れた場合は処理を止め、再確認してから保存し直します。

## 開発・確認

GitHub ActionsでユニットテストとAPK作成を実行します。新しい版を配布する時は`new/version.json`、`CHANGELOG.md`、アプリ内履歴をまとめて更新します。履歴と版番号のチェックに失敗するとビルドを止めます。`old/`は直前の配布タグから用意します。GitHubの更新通知はAPK公開後に変更します。

実機でのインストール・各サービスのログインと取得は、別途端末で確認が必要です。テストやビルド成功は、各サービスの実際の取得成功を保証するものではありません。

配布版は固定した署名で作成します。署名用データはGitHub SecretsのAPP_SIGNING_BUNDLEに保存し、コードやAPKには含めません。未設定時は配布を止めます。debug APKは開発用で、配布版への上書きには使えません。

JDK 17 / Gradle 8.11.1 / Android SDK 35。`python3 scripts/prepare_versions.py` → `python3 scripts/check_release.py` → `gradle :app:testDebugUnitTest :app:assembleDebug`。

ライブラリ：youtubedl-android 0.18.1（GPL-3.0）、yt-dlp（Unlicenseほか依存ライセンス）、FFmpeg（同梱ビルドのライセンス）。アプリのソースはGPL-3.0-or-laterです。[LICENSE](LICENSE)

## SpankBangの試験対応

SpankBangのリンクでは追加の通信部品を自動で使います。ログイン項目の追加はありません。取得を拒否される場合もあり、実際の動画保存は端末で確認が必要です。既存サイトは従来の取得処理を使います。追加部品の出典は[通信部品の情報](docs/spankbang-transport.md)を参照してください。

## TwFilesの保存

TwFiles（twfiles.com）の個別動画リンクを、そのままアプリへ貼り付けて読み込めます。別の保存アプリを入れる必要はありません。動画情報・配信形式の取得まで確認しており、実機での保存完了は未確認です。パスワード付き・フォルダーの一括保存は未対応です。
