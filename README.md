# X-tool / X保存 v1.02

仲間六夜 feat. ChatGPT。自分専用のAndroidアプリ。Android 10以降のarm64端末用（Galaxy S24 Ultraを想定）。

## できること

- 投稿動画・録音済みスペースを取得データから判別。
- 動画はMP4、スペースはM4Aとして保存。
- URL貼り付け／Xの共有からの受け取り。
- 保存前の確認、進捗表示、キャンセル、保存後に開く。
- 保存中はフォアグラウンドサービスで処理。通知は保存中だけ表示。
- 保存先：`Download/X保存/動画/`・`Download/X保存/スペース/`。
- AndroidのMediaStoreを使用し、全ファイルアクセス権限を要求しない。
- 取得エンジンの手動更新。通常の取得で更新待ちは発生しない。

## GitHubでAPKを作る

1. このZIPを展開し、**中身をリポジトリの直下**へアップロードする。`app`、`.github`、`settings.gradle.kts`などが直下にある形。ZIP自体を置くだけではビルドされない。
2. `.github/workflows/build-apk.yml`も必ず含める。スマホのファイル選択で隠しフォルダが見えない場合はGitHubの「Add file → Create new file」で、このパスを指定して内容をコピーする。
3. GitHub → Actions → Build APK。main/masterへのpushで自動実行する。別ブランチなら「Run workflow」で実行する。
4. 成功した実行のArtifacts → `X-tool-v1.02-arm64-APK`をダウンロードする（GitHubログインが必要）。
5. ダウンロードしたZIPを展開し、`app-debug.apk`を開いてインストールする。必要ならブラウザ／マイファイルに「不明なアプリのインストール」を許可する。
6. アプリにリンクを貼り、「保存する」→「はい」。Xから共有して「X保存」を選ぶこともできる。

GitHubはアプリのビルド・配布だけに使う。取得URLや動画・音声をGitHubへ送信しない。Termuxは不要。

## 履歴と一時データ

URL、保存履歴、取得ログを永続保存しない。直近の進捗と結果はアプリのプロセス内だけに保持する。保存したファイル名はファイル自体に残る。

取得情報JSON・断片・途中ファイルはアプリ専用キャッシュ内で処理し、成功・失敗・キャンセル後に削除する。OSの強制停止や電源断で処理が中断された場合、次の取得／エンジン更新時に一時データと未公開の保存データを掃除する。完了したファイルを履歴として再走査しない。エンジン本体とバージョン情報は動作に必要なため保持する。Androidの自動バックアップは無効。

## 初版の対応範囲と確認状況

公開・取得可能な投稿動画と録音済みスペースが対象。ログインが必要な場合は「アカウント」→「新しいアカウントでログイン」から、アプリ内ブラウザでXにログインし、表示名を付けて保存します。複数アカウント（最大20件）を保存・選択でき、表示名変更・再ログイン・端末からの削除ができます。Cookieファイルの書き出しは不要です。外部ブラウザやX公式アプリのログイン状態は読み取りません。Google・Apple経由のログインには対応しません。Xのユーザー名とパスワードを使用してください。X側でWebViewログインが拒否される場合は利用できません。ログインの実機確認は未完了です。

アカウントのログイン状態はAndroid Keystoreの鍵でAES-GCM暗号化し、アプリ専用領域へ保存します。パスワードはアプリのコードから読み取り・保存しません。選択した1アカウントだけを取得に使用し、取得用の一時Cookieファイルは処理後に削除します。ブラウザのCookie・Webストレージ・キャッシュはログイン画面を閉じる際と次回開始時に削除します。OSによる強制終了時には次回開始時に掃除します。アプリをアンインストールすると保存したアカウントは失われます。Xのアカウント自体を削除する機能ではありません。

「アプリの更新を確認」でGitHubのapp-update.jsonを確認します。新しい版があれば配布ページを開けます。APKの自動ダウンロード・自動インストールはしません。署名の異なるAPKへの更新が拒否される場合はアンインストールして再インストールが必要です。アカウントの再ログインが必要ですが、Download内の保存済み動画・音声は残ります。v1.01は検証保留のため更新候補から除外します。

## アプリ内の版の切り替え

最新版v1.02と、一世代前の配布版v1.00の画面・取得処理を同梱します。初回起動は最新版。画面上部の「使用中の版・切り替える」から選択でき、選んだ版は次回起動にも引き継ぎます。アンインストールなしで切り替えでき、保存済みアカウントとDownload内のファイルは残ります。保存中／エンジン更新中は切り替えできません。Xからの共有は選択中の版へ渡します。

旧版v1.00は初期版の処理を維持しているため、ログインは旧来のCookieファイル方式です。保存したアカウントは最新版へ戻ると再び使用できます。APKのインストール問題・Android向け設定・共通ライブラリ・取得エンジン本体は、この切り替えでは元に戻りません。次回の配布では最新版を前の版の枠へ移し、さらに古い版は同梱から外して二世代を維持します。

録音なしで終了したスペース、削除済みデータ、開催前／配信中／録音処理中のスペースは対象外。短縮URL t.co は直接展開しないため、Xの投稿またはスペースのURLを使用する。

X側の変更やアクセス制限により取得できない場合がある。最初に「取得エンジンを更新」を実行する。実機での取得は未検証。GitHub Actionsのビルド成功と、実際の動画・スペース各1件の保存・キャンセル・再生を確認してから使用する。

## 開発・署名

JDK 17、Gradle 8.11.1、Android SDK 35を使用する。`gradle :app:testDebugUnitTest :app:assembleDebug`でテストとAPK生成。Gradle Wrapperは同梱せず、Actionsで指定版Gradleを導入する。

初版はdebug APK。GitHubの実行環境ではdebug署名鍵が再生成される場合があり、別ビルドへの上書きインストールに失敗することがある。その場合は旧アプリをアンインストールして入れ直す（保存済みのDownload内ファイルは保持される）。継続利用時は固定署名鍵へ移行する。
